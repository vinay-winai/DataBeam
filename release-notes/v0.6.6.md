DataBeam v0.6.6 fixes Sendme transfer completion issues exposed by VPN and slower relay connections, updates transfer engine security dependencies, and improves the Croc received-text viewer.

**Upgrading from the preview:** If you downloaded an earlier v0.6.6 preview, re-download the current packages on both devices to get all fixes below. The final preview packages have been promoted to this stable release.

[DataBeam website](https://vinay-winai.github.io/DataBeam/)

## Transfer engine updates

- **Sendme security fixes:** Update iroh-blobs to 0.103.1 to prevent unsolicited uploads into the sender's store. Update Tokio, rustls, WebPKI, and related dependencies with the security fixes carried by official Sendme 0.37.1. The iroh transport remains at 1.0.2.
- **Direct/Relay reporting:** Sendme and EasySendMe receivers display the selected payload connection's route and update it when the path changes. This reporting applies to receivers.
- **Sendme sender completion:** Prevent one-shot senders from reporting Complete and closing after metadata/size probes while the receiver is still waiting to request file data. This timing race can be exposed by slower relay/VPN connections. Completion now requires a successful payload request, and interrupted progress streams cannot imply success.
- **Acknowledged delivery:** Finish each Sendme response and wait for QUIC acknowledgment of all bytes and the end-of-stream marker before reporting request completion. This keeps one-shot senders from stopping while data is still queued on a slower connection. Explicit sender failures cannot become successful completion merely because queued-byte progress reached 100%.
- **CLI interoperability:** Fix plain CLI filenames being treated as directories. Collections without a common enclosing folder are received inside a `_databeam` folder, following the GUI sender's naming convention. Existing sender folders and nested paths are preserved, including during cached exports. Files named `databeam_hash.txt` are preserved.
- **Cache cleanup and errors:** Explicitly close blob databases before cache reuse or removal on Windows. Preserve underlying connection/export error details and the destination path.
- **Croc 11.5.5:** Bundle `11.5.5-databeam`, built from verified official source. Retain the earlier keepalive and route regression coverage against the upstream implementations.
- **Local listener startup:** Adopt Croc's replacement listener startup, which removes the wildcard self-connection check behind errors such as `dial tcp :9013: can't assign requested address`.
- **Croc compatibility fixes:** Fix Windows text reception incorrectly prompting to overwrite its own temporary file. Allow slower relay probe responses, and stop an incomplete probe from falling through into the compressed transfer protocol.

## Received-text improvements

- Replace the disabled text boxes with a Croc web-style received-text panel.
- Add wrapping, bounded scrolling, selection, keyboard navigation, Copy text feedback, and an optional expanded view.
- Preserve complete messages, including long lines, blank lines, indentation, quotes, Unicode, and trailing whitespace. Message contents are handled separately from progress logs.
- Avoid cloning the full message on every rendered frame.

## Validation and downloads

Windows validation includes 86 passing application regression tests, 1 MiB message preservation, an exact clipboard comparison after a live 153 KiB text transfer, and a real EasySendMe ticket-and-payload round trip. Croc direct/relay text and file transfers in both startup orders, plus browser interoperability in both directions, were also verified during the engine upgrade.

All 19 default native Sendme tests pass. They cover delayed metadata/payload requests, exact file bytes, folders, empty files, resumed downloads, CLI wrapping and cached exports, preservation of existing folders, and rejection of unsolicited uploads. A controlled UDP-delay test confirms that the sender waits for delivery instead of completing with response packets still queued.

A separate real public-relay test passed with a 256 KiB CLI-style payload, with the server's IP transport disabled, a receiver Relay event, and exact exported-byte verification. User testing confirmed successful Windows-to-Mac and Mac-to-Windows transfers with VPN enabled on both devices. One Sendme I/O failure immediately after turning VPN off recovered automatically on retry and did not recur in subsequent testing.

The release action builds Windows x64 EXE/ZIP, macOS Apple Silicon and universal DMGs, and Linux x64 DEB/AppImage packages. Local UI validation was performed on Windows; the exact affected Mac/VPN setup has not been independently retested.

This is the **stable v0.6.6 release**, replacing v0.6.5 as Latest.
